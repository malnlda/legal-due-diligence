# 单一 Markdown 底稿工作流

## 一、底稿的定位

底稿是律师内部分析文件，不是资料收件台账，也不是对外报告的半成品。底稿应让律师直接看到：材料记载了什么、不同材料能否相互印证、哪些事实已经查清、哪些判断仍受限制、这些事项对本项目意味着什么。

底稿可以坦率记录疑点、补件需求和待决问题。它不必为了客户阅读体验删除这些内容，但应避免用大表格替代分析。

撰写阶段全程使用 Markdown。整个底稿完成、律师明确指令后，才按 [docx-format.md](docx-format.md) 转换为 DOCX；转换前不生成任何 DOCX。

## 二、项目文件

### 新建项目

如果项目尚无主底稿，创建：

`关于[标的公司全称]的法律尽职调查底稿.md`

该文件文首至少包含：

- 项目信息：委托人、标的公司、项目目的、基准日、经办律师；
- “内部工作文件，请勿对外使用”的醒目标识；
- **定义与写作约定区**：本项目选定的称谓（如“标的公司”或“目标公司”，以项目交易文件的定义为准）、各方简称、日期格式、金额格式、序号体系。每轮续写前必须先读取本区并遵守，续写中新设的简称随即补录；
- 根据项目实际确定的章节目录；
- 尚未开展的章节仅保留章标题，不预填大量空表格和检查项。

标准十章只是默认导航，项目可增删、合并或重命名章节。不要为了凑齐十章保留不适用内容。

建立骨架的当轮对话中，可以在对话里（不落盘、不建文件）给出一份简要的“材料—章节”归类总览和建议的分析顺序，帮助律师安排后续各轮章节。该总览只是导航提示，不是齐备性判断。

### 已有底稿

优先编辑现有主底稿。不要另建“修改稿 2”“第 X 章更新稿”或带时间戳副本。保留用户已有格式和已经作出的实质修改，只在目标章节内进行必要更新。

除非律师要求，不在正文加入“第几批材料更新”标签。材料日期和文件来源已经能够承担追溯功能，批次标签容易打断阅读。

## 三、一次只写一章，顺序续写

一次对话只完成一个实质章节。若用户一次要求多个章节：

1. 先确认最优先章节；
2. 完成该章材料分析、写作和校验；
3. 在后续对话继续下一章。

用户明确要求全文机械合并、统一样式、接受修订或检查一致性时，可以一次处理全文，因为这不涉及同时生成多个章节的法律分析。

续写遵守以下纪律：

1. 本轮内容写入既有文稿中该章节应在的位置（通常为文稿末尾或对应空标题下），形成“前文 + 本章”的完整新稿；
2. 不改动已写好的前文，包括不“顺手”统一前文用语、调整前文格式或补充前文内容；
3. 续写中发现前文存在事实错误、数据矛盾、遗漏或与本章勾稽不一致的，在对话中向律师逐项报告，由律师决定是否修改；未经指令不得回改；
4. 律师明确指令修订某一前文章节的，该轮即以该章节为本轮唯一目标章节，按同样标准深度修订。

## 四、章节分析顺序

### 1. 界定本章要回答的问题

结合已经确定的项目目的或委托范围提出少量、具体的问题。以下示例分别对应不同项目类型，只按实际情况选用，不累计适用：

- 股权收购项目可关注拟转让股权的权属、限制及控制权变更后果；
- 资产收购或业务承接项目可关注核心资产、合同、许可和人员能否依法转移或继续使用；
- 增资或合资项目可关注出资能力、出资形式、治理安排和业务资源投入；
- 融资项目可关注偿债能力、担保效力、权利顺位和融资条件；
- 一般合规核查可关注现状是否合法、整改责任及持续经营影响。

不得直接把通用尽调清单当作本章结论框架。

### 2. 建立内部证据图

在工作记忆中按“问题—证据—矛盾—暂定判断”组织材料，不必另存一份证据台账。至少完成下列核对：

- 同一事实在章程、工商档案、审计报告、合同和公司说明中的记载是否一致；
- 金额能否加计，期初与期末是否衔接；
- 文件签署主体、签署日期、有效期和履行状态是否匹配；
- 证书反映的是签发时状态还是基准日状态；
- 公司说明是否有其他材料支持。

### 3. 先写事实，再写意见

事实段应完整交代材料内容。典型顺序是：

1. 来源和文件性质；
2. 关键条款或数据；
3. 与其他材料的勾稽结果；
4. 尚不能确认的边界。

意见段再说明：

1. 适用的法律规则或交易要求；
2. 事实是否满足该规则；
3. 风险如何发生、会影响什么；
4. 建议由谁在何时采取什么措施。

## 五、每章建议结构

以下结构是默认方案，可根据材料复杂程度调整：

### （一）核查范围与项目问题

说明本章围绕什么交易问题核查了哪些事项。避免罗列所有可能文件。

### （二）核查材料

用简短段落或紧凑列表列出实际使用的核心材料。材料很多且需要查找时，可使用“序号、材料名称、日期/期间、备注”四列表格。不得为每个文件增加“形式、状态、重要程度、批次、置信度”等流程字段。

### （三）核查事实与分析

这是底稿主体。按实质问题设置必要的小标题，用连续段落详细展开。每个重要事实均应能够追溯到具体文件或公开来源。

对合同、章程、审计报告等材料，不能只写“已提供”“经审阅未见异常”。应摘述足以支持判断的主体、金额、期限、主要权利义务、限制条件、履行状态或审计意见。

### （四）初步结论与风险

分别说明已经能够确认的结论、存在的风险和判断限制。风险应写清事实基础、法律或交易逻辑、可能后果和建议措施。内部风险等级仅在项目确有分级需要时使用，不用表情符号装饰。

### （五）待律师决定事项

仅列需要律师结合项目策略决定的问题，如：是否接受某项说明、是否扩大核查范围、是否把某事项列为签约前提、是否需要专项法律检索。

### （六）建议补充资料

只列分析后确有必要补充的材料。每项说明：

- 要核实的具体事实；
- 为什么现有材料不能回答；
- 该事实与项目目标或法律判断的关系；
- 可接受的替代材料或核验方式（如有）。

不要因为通用清单列有某项材料，就当然要求补充。

## 六、详实程度

“详实”不是机械追求篇幅，而是确保每个影响判断的要素均已展开。以下情形通常说明写得过于简略：

- 只列文件名，不写文件内容；
- 一段同时概括多份相互独立的材料，却没有日期、金额或关键条款；
- 只写“符合规定”“存在风险”，未说明依据和影响；
- 把事实和建议压缩进一张多列表格；
- 为每个问题只写一句结论，读者无法复核推理过程。

如果材料多，宁可增加事实段落和必要的小标题，也不要把正文压缩成标题加短句。

## 七、表格门槛

只有同时满足下列条件时才使用表格：

1. 各行是同类记录；
2. 各列字段稳定；
3. 横向比较或快速查找明显优于连续叙述；
4. 单元格不需要容纳成段法律分析。

通常适合表格的内容包括公司基本登记信息、股权结构、历史变更、知识产权清单、主要合同目录和多年财务数据。合同条款分析、风险论证、补件理由和律师意见通常使用段落。

相邻两节均使用表格时，重新判断其中至少一节能否改成段落。表格内出现多个长段落时，应拆回正文。

## 八、补充材料到达后的更新

收到补充材料后：

1. 只修改受影响章节；
2. 把新材料与原有事实和结论重新勾稽；
3. 删除已经失效的疑点或补件建议，而不是保留“风险已消解”的流水账；
4. 如结论变化，直接重写相关段落并向律师说明变化原因；
5. 不自动生成新版本文件或批次报告；
6. 受影响章节已有对应报告章节的，在对话中提示律师该报告章节可能需要相应修订，但不自动修改报告。

## 九、完成后的对话摘要

用简短文字告诉律师本章的结论、关键矛盾、待决定事项和建议补件。该摘要只在对话中呈现，不另存为“核验报告”或“成果目录”。
