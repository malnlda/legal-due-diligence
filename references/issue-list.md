# 主要法律问题清单

## 一、定位

主要法律问题清单（下称"问题清单"）是面向委托人的独立文件。它把尽调发现的、需要采取处理措施的法律问题集中列出，并在每一个问题的条目中直接写明处理措施，使委托人不必通读报告即可了解本次尽调的主要问题和处理办法。问题与处理措施写在同一条目中，不另设"解决方案"部分，也不另建文件。

问题清单不对问题分级。交易类项目按处理时点分为"先决条件"和"交割后处理事项"两组；非交易类项目只列一份清单。

问题清单是可选环节，只有律师明确要求时才起草。

## 二、起草时点

律师可以选择以下任一时点，也可以两个时点都做（报告后的版本取代报告前的版本）：

| 时点 | 依据 | 适用情形 |
|---|---|---|
| 报告前 | 已完成并经律师审阅的底稿 | 需要尽快向委托人反馈问题，用于谈判和交易文件起草；报告随后出具 |
| 报告后 | 报告初稿（或定稿），必要时参考底稿 | 作为报告的摘要文件随报告交付，或在报告之后单独交付 |

律师未说明时点的：报告文件已有实质章节的，按"报告后"处理；只有底稿的，按"报告前"处理。仍不能确定的，询问律师。

### 报告前起草的特别要求

1. 底稿应已覆盖律师指定的全部章节；未写完的章节，在交付说明中列明，不在清单中臆测；
2. 只纳入已经查明事实基础的问题。底稿中仅因材料缺失而无法判断的事项，属于补件问题，不写入问题清单；其中可能构成重要问题的，在交付说明中提出，由律师决定是否补件或如何表述；
3. 底稿"待律师决定事项"中尚未决定的问题，不擅自写入清单，在交付说明中列出；
4. 此后撰写报告章节时，如发现报告的事实、定性、处理措施或归组与清单不一致，在该轮交付说明中报告，由律师决定修改哪一份文件；不自动修改清单。

### 报告后起草的特别要求

1. 清单中的事实、定性和措施不得超出报告；不得新增报告没有分析过的问题；
2. 每个问题注明对应的报告章节；
3. 清单的处理措施和归组应与报告"结论与风险提示"一致；不一致的，在交付说明中报告；
4. 报告此后修订的，在交付说明中提示清单可能需要相应修订。

## 三、项目类型与清单形式

### 1. 判断项目类型

以已经确定的项目目的或委托范围判断：

- **交易类项目**：拟议交易设有交易文件约定的完成节点，即委托人须在某个时点付款或取得权益，例如股权收购或资产收购的交割、增资或投资的投资款支付、合资公司的设立或出资。只要存在这样的节点，就同时存在交割先决条件和交割后处理事项。适用本节第 2 小节的分组清单。
- **非交易类项目**：不发生交易、没有交割节点的调查，例如内部合规核查、合规管理体系建设前期调查、为日常管理目的进行的法律体检。适用本节第 3 小节的单一清单。

项目目的不能可靠判断属于哪一类的，询问律师，不得自行假定。律师对清单形式另有要求的，从其要求。

### 2. 交易类项目：分为两组

第一组为"交割先决条件"，收录须在签约、交割或委托人付款前完成、取得或作出安排的事项。判断标准是：该问题未处理完毕，委托人不应签署交易文件或支付款项。通常包括：取得相关方的确认函、同意函或承诺函；补足出资、清理代持、解除或终止相关协议；停止正在发生的违约或违规行为，或者取得相对方的认可；签署或重新签署必要的协议；就已经查明的具体问题在交易文件中约定特别赔偿或由相关方承担责任；需要调整交易结构、价格或付款安排的事项。须在签约前解决的事项也列入本组，并在条目中写明"在签署交易文件前"。

第二组为"交割后处理事项"，收录不影响交割和付款、可以在交割后限期完成的事项。通常包括：办理备案、登记或许可；设立分支机构；将相关资产转入标的公司名下；完善内部制度、财务核算和纳税申报；规范持续经营中的不合规做法。条目中写明完成期限，或者写明"在交易文件约定的期限内"完成。

两组名称固定，不因交易类型而变化：交易类项目一律使用"交割先决条件"和"交割后处理事项"，投资、增资、融资、股权收购、资产收购、合资均同。交易文件或律师另有用语（如"投资先决条件""付款条件"）的，从其用语。

归组规则：

1. 以该问题的处理措施最早须在何时完成为准，不以问题的轻重为准；
2. 一个问题既有交割前须完成的措施，又有交割后须继续完成的措施的，列入第一组，并在同一条目中写明交割后的部分，不在两组中重复列示；
3. 只能通过交易文件中的特别赔偿、承诺等条款处理的具体问题，列入第一组，措施写为"在交易文件中约定……"；不针对具体问题的一般性陈述与保证（如不存在未披露的债务和对外担保），不列入清单；
4. 问题无法通过上述措施解决、可能影响交易能否推进的，列入第一组，措施写明对交易结构、价格、付款安排或交易进度的影响和建议，并在交付说明中提请律师注意；
5. 归组存在疑问的，按较早的时点归组，并在交付说明中提请律师确认。

### 3. 非交易类项目：一份清单

不分组，所有问题连续编号。处理措施写为整改或规范措施，写明责任主体（标的公司或其具体部门、相关股东或人员）和完成期限或时点要求（如"立即停止""在[期限]内完成"）；不使用先决条件、陈述与保证、价款调整等交易工具。

### 4. 不分级

两类项目均不对问题分级，不使用"一级""二级""重大问题""一般问题"等等级标签，不使用字母、颜色、表情符号或星号标示轻重。问题的轻重通过事实和后果的具体描述体现。律师明确要求分级的，从其要求，分级标准由律师确定。

## 四、收录范围与排列

### 1. 收录范围

收录依据文件（底稿或报告）中需要标的公司、相关方或交易文件采取具体措施的全部问题，包括影响较小、但需要办理备案或完善制度的事项。仅需委托人知悉、不需要采取任何措施的事项不收录。律师要求只列主要问题的，从其要求。

不得遗漏底稿或报告中已经认定并已提出处理措施的问题。

### 2. 合并与拆分

同一事实引起的多个后果写为一项。同一主体、同一性质的若干事实可以合并为一项，如多处经营场所均未办理分支机构登记。不同事实不得为凑数拆分或合并。

### 3. 排列

组内（非交易类项目为全清单）按报告章节顺序排列；同一章节有多项的，影响较大的在前。每组从 1 开始编号。

## 五、文件与结构

文件名：`关于[标的公司]的主要法律问题清单.md`（律师另有命名的从其命名）。一个项目只维护一份；报告后版本直接在原文件上重写，不另建副本。

报告前版本已经按 [docx-format.md](docx-format.md) 转换为 DOCX 并交付的，DOCX 即为该清单的有效稿。此后起草报告后版本时，直接在 DOCX 上修订，保留律师已作的批注、修订和格式；已归档的 Markdown 不再更新，也不应据以重新生成 DOCX 覆盖已有批注。此规则与 [docx-format.md](docx-format.md) 第一节一致。

结构如下：

1. 标题："关于[标的公司全称]的主要法律问题清单"；交易类项目也可以用"[项目名称]项目主要法律问题清单"；
2. 说明段：一段，写明清单的依据、基准日以及与报告的关系。报告前版本写"本清单系本所律师根据截至[基准日]对标的公司提供资料的审阅及公开信息查询结果整理，详细事实和分析将在法律尽职调查报告中载明"；报告后版本写"本清单系根据本所出具的《关于[标的公司]的法律尽职调查报告》整理，各问题的详细事实和分析见报告相应章节"。交易类项目接写"清单按处理时点分为交割先决条件和交割后处理事项两部分"。统一限定在此处作一次简要说明，或引用报告的"声明与限定条件"；
3. 正文：交易类项目设"一、交割先决条件""二、交割后处理事项"两个组标题，组下为编号条目；非交易类项目不设组标题，直接列编号条目。组标题用"一、""二、"，条目用阿拉伯数字加顿点（"1.""2."），每组或不分组的清单从 1 开始连续编号；
4. 默认不设致送语和落款。律师要求的，在标题后加"致：[委托人全称]"，在文末加律师事务所、经办律师和日期。

全文使用编号段落，不使用表格。

## 六、条目写法

每个问题写为一个编号段落，问题和处理措施在同一段内完成，不设"问题事实""风险及后果""解决方案"等小标题。一个条目依次写明：

1. **已查明的问题**：核心事实，确定性陈述；主体、金额、比例、日期和协议名称写准确，人员使用姓名或职务全称，不使用非正式称谓；
2. **对项目的影响**：只在影响不自明或影响到措施选择时写，写具体后果（如违约金金额、可能的行政处罚、权属争议），不展开法律论证；确有必要时点明法律依据名称和条款；
3. **处理措施**：写明由谁、做什么、形成什么文件或结果、何时完成。交易类项目第一组写交割前须完成的行为或须取得的文件，可以附带交易文件中的赔偿或承诺安排；第二组和非交易类项目写明完成期限，不单独使用"尽快"。有替代方案的，用"或者"并列写明。

报告后版本在条目末尾以括号注明对应的报告章节，如"（详见报告第三章第（二）节）"。

篇幅一般为二至五句。事实复杂的可以稍长，但不在清单中复述报告的论证过程；一个条目需要写成两段以上的，先考虑是否应当拆分为两项。每个条目都应是完整的句子，不写成短语或标题。

措施的主语是标的公司、相关股东或人员、交易各方或交易文件。"建议持续关注""建议补充材料""要求标的公司补充提供材料以便核实"不是处理措施。

### 范例（虚构信息）

交易类项目（增资）：

> 一、交割先决条件
>
> 1. 股东张某于2019年认缴的人民币500万元出资，出资款实际来源于甲公司的资金，在法律上构成出资不实。张某应在交割或投资款支付前向甲公司补足人民币500万元出资，并提供银行入账凭证。
>
> 2. 甲公司在《区域经销协议》约定的授权地域以外销售乙公司品牌产品，违反该协议的地域限制，乙公司有权依约主张人民币100万元违约金。甲公司应立即停止在授权地域以外的销售，或者取得乙公司的书面认可；交易文件中应约定，因该事项产生的违约金及其他损失由实际控制人承担。
>
> 二、交割后处理事项
>
> 1. 甲公司以特许经营方式发展加盟商，尚未向商务主管部门办理商业特许经营备案，《加盟合同》亦欠缺法定必备条款。甲公司应在交割后[期限]内修订《加盟合同》并完成备案。
>
> 2. 甲公司在丙市、丁市的两处仓库实际从事经营活动，尚未办理分公司登记。甲公司应在交割后[期限]内为上述仓库办理分公司登记，并由分公司在当地为员工缴纳社会保险和住房公积金。

非交易类项目（内部合规核查）：

> 1. 甲公司与高级管理人员签订的《竞业限制协议》约定离职后无需支付经济补偿，与《中华人民共和国劳动合同法》第二十三条的规定不符，相关竞业限制约定可能无法约束离职人员。甲公司人力资源部应在[期限]内与相关人员重新签订竞业限制协议，约定竞业限制期间按月支付经济补偿。
>
> 2. 甲公司存在以出纳个人银行账户收取货款的情形。甲公司应立即停止以个人账户收付款，将个人账户中的公司资金全部转入公司账户，并由财务部在[期限]内修订资金管理制度。

## 七、写作规则

1. 问题清单是客户文件，适用 [report-writing.md](report-writing.md) 的全部口径规则，特别是第五节：不得出现"现有材料不能证明""无法确认""未提供"等调查限制式表述；
2. 适用 [legal-style.md](legal-style.md) 的文风和中文规则；
3. 交易类项目的措施针对项目目的选择交易工具或整改措施；非交易类项目的措施为整改或规范措施；
4. 不使用"重大风险""严重"等渲染性词语替代具体后果描述；
5. 不使用表格，不以粗体短语充当条目标题。

## 八、工作方式

1. 问题清单属于跨章节汇总，可以在一次对话中完成全文，不受"一次对话只写一个章节"的限制。问题较多、律师要求分轮的，交易类项目可以按组分轮起草；
2. 起草前通读依据文件（底稿或报告）的全部"初步结论与风险"或"律师意见"和"结论与风险提示"部分；
3. 交付时在对话中说明：
   - 起草时点和依据文件；
   - 项目类型的判断及所采用的清单形式；
   - 各组（或全清单）的问题数量；
   - 归组存在疑问、需要律师确认的问题；
   - 底稿或报告中已识别但未纳入清单的问题及理由（如不需要采取措施、属于补件问题、待律师决定）；
   - 与报告或底稿不一致之处（如有）。
4. 律师下达转换指令后，按 [docx-format.md](docx-format.md) 单独转换为 DOCX；问题清单可以先于报告转换和交付；
5. 清单已转换为 DOCX 的，此后的报告后版本在 DOCX 上修订，不重写已归档的 Markdown（见第五节）；
6. 按 0.4.0 及以前版本的"分级清单加分级解决方案"格式起草的既有清单：律师未要求改版的，按原格式继续修订；律师要求改版的，按本文件重写，已转换为 DOCX 的，先提示律师改版可能无法保留已有批注，由律师决定是否在新文件中重写。
