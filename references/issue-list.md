# 重大问题清单及分级解决方案

## 一、定位

重大问题清单及分级解决方案（下称“问题清单”）是面向委托人的独立文件。它把尽调发现的重要问题集中列出，按严重程度分级，并为每个问题提出具体的解决方案，使委托人不必通读报告即可了解本次尽调的主要问题和处理办法。

问题清单是可选环节，只有律师明确要求时才起草。

## 二、起草时点

律师可以选择以下任一时点，也可以两个时点都做（报告后的版本取代报告前的版本）：

| 时点 | 依据 | 适用情形 |
|---|---|---|
| 报告前 | 已完成并经律师审阅的底稿 | 需要尽快向委托人反馈问题，用于谈判和交易文件起草；报告随后出具 |
| 报告后 | 报告初稿（或定稿），必要时参考底稿 | 作为报告的摘要文件随报告交付，或在报告之后单独交付 |

律师未说明时点的：报告文件已有实质章节的，按“报告后”处理；只有底稿的，按“报告前”处理。仍不能确定的，询问律师。

### 报告前起草的特别要求

1. 底稿应已覆盖律师指定的全部章节；未写完的章节，在交付说明中列明，不在清单中臆测；
2. 只纳入已经查明事实基础的问题。底稿中仅因材料缺失而无法判断的事项，属于补件问题，不写入问题清单；其中可能构成重大问题的，在交付说明中提出，由律师决定是否补件或如何表述；
3. 底稿“待律师决定事项”中尚未决定的问题，不擅自写入清单，在交付说明中列出；
4. 此后撰写报告章节时，如发现报告的事实、定性、分级或措施与清单不一致，在该轮交付说明中报告，由律师决定修改哪一份文件；不自动修改清单。

### 报告后起草的特别要求

1. 清单中的事实、定性和措施不得超出报告；不得新增报告没有分析过的问题；
2. 每个问题注明对应的报告章节；
3. 清单的分级和措施应与报告“结论与风险提示”一致；不一致的，在交付说明中报告；
4. 报告此后修订的，在交付说明中提示清单可能需要相应修订。

## 三、分级标准

默认分为三级。分级以项目目的为基准，同一事实在不同项目中的等级可能不同。律师已有分级标准或对个别问题作出分级的，以律师意见为准。

**一级（重大问题）**：可能导致项目目的无法实现、交易无效或无法推进，或者可能使委托人承担重大经济损失或严重法律责任。原则上应在签约或交割（或项目实施）前解决，或取得明确、可执行的安排；无法解决的，应考虑调整交易结构、价格或暂缓推进。

**二级（较大问题）**：可能使委托人承担较大经济损失或法律责任，或影响交易条件，但可以通过交易文件安排（陈述与保证、特别赔偿、价款调整、分期支付、共管）、交割后限期整改或其他措施加以控制。

**三级（一般问题）**：合规瑕疵或管理性问题，对项目影响有限，可以通过交割后整改、规范运营或日常管理解决。

默认收录三级问题；律师要求只列一级、二级的，从其要求。三级问题的方案可以写得简短。

不使用字母或英文缩写分级，不使用颜色、表情符号或星号标示等级。

## 四、文件与结构

文件名：`关于[标的公司]的法律尽职调查重大问题清单及解决方案.md`（律师另有命名的从其命名）。一个项目只维护一份；报告后版本直接在原文件上重写，不另建副本。

报告前版本已经按 [docx-format.md](docx-format.md) 转换为 DOCX 并交付的，DOCX 即为该清单的有效稿。此后起草报告后版本时，直接在 DOCX 上修订，保留律师已作的批注、修订和格式；已归档的 Markdown 不再更新，也不应据以重新生成 DOCX 覆盖已有批注。此规则与 [docx-format.md](docx-format.md) 第一节一致。

结构如下：

1. 标题：“关于[标的公司全称]法律尽职调查重大问题清单及分级解决方案”；
2. 致送语：“致：[委托人全称]”；
3. 说明段：写明清单的依据、基准日、分级标准摘要以及与报告的关系。报告前版本写“本清单系本所律师根据截至[基准日]对标的公司提供资料的审阅及公开信息查询结果整理，详细事实和分析将在法律尽职调查报告中载明”；报告后版本写“本清单系根据本所出具的《关于[标的公司]的法律尽职调查报告》整理，各问题的详细事实和分析见报告相应章节”。统一限定在此处作一次简要说明，或引用报告的“声明与限定条件”；
4. 第一部分“重大问题清单”：按一级、二级、三级分组，每组内按重要性排序，连续编号。每个问题写一个标题句和一至三句摘要（核心事实和对项目的影响），报告后版本注明对应的报告章节。使用编号段落，默认不使用表格；
5. 第二部分“分级解决方案”：按第一部分的顺序和编号，逐个问题写明：
   - 问题事实：已查明的事实及来源，确定性陈述；
   - 风险及后果：适用的规则（有实质分析关系时引用法律依据）以及对项目的具体影响；
   - 解决方案：具体措施、责任主体、完成时点或所处的交易阶段、对应的交易文件工具；有替代方案的一并写明；问题无法解决时，对交易安排的影响和建议；
6. 落款：律师事务所、经办律师、日期。

第二部分使用连贯段落；可以用“问题事实”“风险及后果”“解决方案”作为每个问题下的固定小标题，但每个小标题下应是完整的句子和段落，不写成短语。

## 五、写作规则

1. 问题清单是客户文件，适用 [report-writing.md](report-writing.md) 的全部口径规则，特别是第五节：不得出现“现有材料不能证明”“无法确认”“未提供”等调查限制式表述；
2. 适用 [legal-style.md](legal-style.md) 的文风和中文规则；
3. 解决方案应针对项目目的选择工具，不得对所有问题统一写“建议持续关注”“建议补充材料”。“要求标的公司补充提供材料以便核实”不是解决方案；
4. 合并同源问题：同一事实引起的多个后果写为一个问题；不同事实不得为凑数拆分或合并；
5. 不使用“重大风险”“严重”等渲染性词语替代具体后果描述；等级由分级标准确定，不由形容词表达；
6. 不得遗漏底稿或报告中已经认定的重要风险。

## 六、工作方式

1. 问题清单属于跨章节汇总，可以在一次对话中完成全文，不受“一次对话只写一个章节”的限制。问题较多、律师要求分轮的，可以按等级分轮起草；
2. 起草前通读依据文件（底稿或报告）的全部“初步结论与风险”或“律师意见”和“结论与风险提示”部分；
3. 交付时在对话中说明：
   - 起草时点和依据文件；
   - 各级问题数量；
   - 底稿或报告中已识别但未纳入清单的风险及理由（如等级过低、属于补件问题、待律师决定）；
   - 分级理由存在疑问、需要律师确认的问题；
   - 与报告或底稿不一致之处（如有）。
4. 律师下达转换指令后，按 [docx-format.md](docx-format.md) 单独转换为 DOCX；问题清单可以先于报告转换和交付；
5. 清单已转换为 DOCX 的，此后的报告后版本在 DOCX 上修订，不重写已归档的 Markdown（见第四节）。
