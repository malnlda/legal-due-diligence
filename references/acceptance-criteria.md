## 一、章级验收标准（每章完成后对照）

以下 7 条**全部满足**，方可将该章状态标为"已自检"：

| # | 检查项 | 判定方式 |
|---|--------|---------|
| AC-C1 | §X.4 调查发现中**每项发现**都注明了信息来源（"经查阅 XX"、"据 YYYY-MM-DD 元典接口数据"等） | 逐条扫描，无裸露的无来源陈述 |
| AC-C2 | §X.4 中涉及金额、日期、比例处**无概括性表述**（无"约"、"若干"、"数月"等模糊词） | 关键词检测 |
| AC-C3 | §X.3 已列出**所有未获取材料**并逐项说明对本章调查结论的影响 | 与 dd-checklist 对应章未收/部分项交叉核 |

| AC-C5 | 外部 API 数据（yd-enterprise-info）若已使用，**不得**列入 §X.2；§X.4 段首注明"经查阅元典开放平台接口（调用时间 YYYY-MM-DD HH:MM，原始数据见 raw/chineselaw/<文件名>）"；API 数据与目标公司材料冲突处已在 §X.5 标注 🟡/🔴 风险 | 有 API 数据时逐条核 |

**注**：上述自检由 AI 执行，结果写回 task-board.md 对应章的"自检备注"列；自检未通过的项列为断点事项，不得自行放行。

## 三、资料齐备性专项说明（律师认定驱动）

> **核心原则（不可修改）**：资料齐备性认定不属于自动验收项。AI 只产出研判意见，律师认定是唯一权威状态。  
> - AC-P2 的"律师认定"列由 `adjudicate` 模式经律师指示写入，任何脚本/自动流程不得改写。  
> - 律师认定默认值必须是"**待认定**"，绝不能默认"已齐备"。  
> - 推进闸门（能否出报告）以律师认定为准，AI 研判列不作为闸门依据。
