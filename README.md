# legal-due-diligence

面向中国公司类法律尽职调查的写作技能：以单一底稿逐章分析材料，由律师判断是否补件；律师要求出报告后逐章转化为正式尽调报告；首先撰写 Markdown文稿，待整稿完成、律师指令后按参考终稿样式转换为排版良好的 DOCX。

## 工作方式

```
确定项目问题 → 逐章阅读材料 → 顺序续写同一份 Markdown 底稿 → 律师判断是否补件
→ 逐章转为报告 → 法律文风复核 → （律师指令后）转换为 DOCX 成稿
```

核心约定：

- **一个项目只有两份文稿**：一份底稿、一份报告（各自先为 Markdown，定稿后转 DOCX）。
- **一次对话只写一章**，在既有文稿基础上顺序续写，不改动已写好的前文；发现前文问题在对话中报告，由律师决定。
- **先事实、后意见**：事实段完整交代材料内容和勾稽关系；律师意见完成「事实 → 规则 → 判断 → 影响 → 建议」的推理链。
- **少用表格**：只有基本登记信息、股权结构、历史变更等结构化数据才用表格；法律分析一律用连贯段落。
- **报告不堆缺件**：底稿可以坦率记录缺件和疑点；进入报告的缺件表述必须逐项通过“报告必要性判断”。
- **报告全文中文**：仅证照编号、域名、依法登记的外文名称等无法回避的原文可以保留。

## 使用示例

底稿阶段：

> 使用 $legal-due-diligence 分析「股权结构与股东信息」章节。项目目的为购买目标公司股权，材料路径为……，请续写主底稿……md。

报告阶段：

> 使用 $legal-due-diligence，根据主底稿和原始材料撰写报告「股权结构与股东信息」一章，续写报告……md。按报告口径过滤缺件表述，保留实际影响出资和控制权安排的风险。

成稿阶段：

> 报告已写完并经我审阅，请按 docx-format.md 的版式把……md 转换为 DOCX。
